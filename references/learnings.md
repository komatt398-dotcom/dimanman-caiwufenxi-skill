# 可复用方法累积（Learnings）

> 本文件只在用户明确要求「更新 / 固化 / 沉淀 skill」时修改。普通财报分析任务不得自动追加经验。

## 2026-08-12 (v3.0.0) | 从章节报告升级为管理诊断

- **根因**：v2 视觉和话术已有明显改善，但指标口径、来源追溯、claim 分级和决策价值仍不足。固定章节容易让报告“完整但不锋利”。
- **新做法**：先生成 `analysis_bundle.json`，再生成 HTML。bundle 记录 disclosures、metrics、calculations、claims、issues、scenarios、actions 和 quality；HTML 是展示层，不是事实源头。
- **结构变化**：固定七段改为固定决策底座 + 动态模块。每份报告只选 2-4 个真正重要的经营问题，并完成 judgment -> evidence -> mechanism -> attribution -> boundary -> action -> indicator -> falsifier。
- **五问变化**：事实、解释、质量、影响、反证保留为后台审计逻辑，不再要求每章显性展示五问自检。
- **同行价值**：同行不是排名章节，只回答“行业共性还是公司问题”。C 级可比不写优劣结论。
- **情景价值**：情景分析只在结果会改变管理动作时使用；关系弱时做风险树，不编精确测算。

## 2026-08-12 | Haier / TCL 回归风险

- **Haier**：解释 18 号导致质保费用从销售费用重分类到营业成本，销售费用率改善不能直接写成真实费用优化。收入重列会影响同比可比性。
- **TCL 中环**：不能混用归母净利率和合并口径销售净利率。亏损分析不能只说减值导致，必须区分主业负毛利、减值、折旧摊销和现金流。人员结构变化不能直接推导裁员或组织效率改善。
- **现金桥**：利润到经营现金流桥与资金流动桥必须区分；现金净变动是终值，不应再次作为增量累加。
- **图表**：费用率趋势优先折线；桥图必须连续；横向条有标签时去横轴；债务图内不塞长段诊断文字。

## 2026-08-12 | 视觉获得感

- 读者不喜欢深蓝压迫式首屏，偏好米白、暖灰、克制公司色。
- 大段落之间可以有轻微分隔，章节内部避免过多横线。
- 正文和图表宽度需要一致；图题、takeaway、单位在图上方。
- 重点要通过有限度粗体、风险红和下划线表达，不靠密集大段文字。
- 可枚举事实、影响、分析、红线和必盯指标必须分行，避免连续重复 `1.`。

## 2026-08-13 (v3.1.0) | 经营者表述验证与去 AI 话术

- **根因**：v3.0 已强化来源边界和 bundle 审计，但报告仍容易出现模型式命名、咨询黑话和“图表有形式感但没有降低理解成本”的问题。
- **新主线**：管理是语言活动；财务分析不仅看报表数字，还要验证经营者在年报 MD&A、业绩说明会、投资者关系活动记录和公开路演中说过的话。
- **来源分工**：财务数字、会计口径和审计事项以定期报告、审计报告和公告为准；业绩说明会、IR 记录和路演只作为管理层解释来源。
- **报告写法**：同一事项同时出现在财报和路演中时，先写财报披露，再写管理层公开交流补充，最后写财务数据支持、部分支持、尚不能验证或相矛盾。
- **语言修正**：避免“收缩式提质”“增长换挡期”“剪刀差扩大”“现金转换驾驶舱”“优先行动卡”等模型式包装，改用财务术语和公开场合自然语言。
- **图表修正**：管理层表述相关图表不能做语录墙，应做表述-验证矩阵、判断-兑现时间线或指标对照。
